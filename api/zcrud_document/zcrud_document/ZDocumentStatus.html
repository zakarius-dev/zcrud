ZDocumentStatus

ZDocumentStatus enum

État du cycle de vie d'un ZStudyDocument (upload → validation → prêt).

L'ordre de déclaration est normatif : le générateur zcrud décode un enum par nom et, pour un champ non-nullable sans valeur par défaut, son repli défensif (invariant AD-10) est la première constante déclarée. Réordonner cet enum changerait silencieusement le comportement défensif de ZStudyDocument.status.

Pourquoi uploading en premier (les replis possibles ne sont pas équivalents) :

  • ready mentirait sur la disponibilité d'un document non prêt (ouverture cassée côté viewer) ;
  • rejected est un état transitoire en principe jamais persisté (la carte optimiste est purgée) ⇒ repli destructeur d'affichage ;
  • uploading affiche « Traitement… » : ne détruit rien, ne ment sur rien.
