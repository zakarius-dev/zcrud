listParentIds method

Future<ZResult<List<String>>> listParentIds()

Énumère les identifiants des parents existants côté distant, pour une topologie « scopée par dossier ».

Pourquoi ce membre appartient au contrat, pas à l'implémentation

Un membre livré uniquement sur un adaptateur concret est statiquement inatteignable depuis une fabrique qui rend le port neutre ZStudyRepository<T> : la seule voie serait un cast vers le type concret — c'est-à-dire renoncer à l'abstraction que l'invariant AD-5 protège, pour une opération qui relève précisément du repository.

Contrat

Un dépôt figé sur un unique parent ne couvre que celui-ci : sans cette énumération, un hôte multi-dossiers doit deviner la liste avant de construire ses dépôts, et sa seule source est le store local — donc rien sur un appareil neuf. sync() rendrait alors Right(unit) sur une liste vide : un succès silencieux indiscernable de « l'utilisateur n'a rien ».

Défaut : Left(ZUnsupportedOperationFailure) — un dépôt dont la topologie n'a pas de parent (plate, globale) ou qui n'implémente pas la découverte le dit explicitement. Jamais une liste vide, qui serait exactement le mode dégradé silencieux que ce membre existe pour éliminer.

Implementation

Future<ZResult<List<String>>> listParentIds() async =>
    Left<ZFailure, List<String>>(
      const ZUnsupportedOperationFailure(
        'listParentIds() n\'est pas supporté par ce dépôt : la topologie n\'a '
        'pas de parent à énumérer, ou la découverte n\'est pas implémentée. '
        'Un Left explicite, jamais une liste vide silencieuse.',
        operation: 'listParentIds',
      ),
    );
