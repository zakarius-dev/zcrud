Résout le libellé de key par composition (AD-13) : ZcrudScope.labels?.maybeResolve → ZcrudLocalizations (delegate) → table en de repli → fallback ?? key.

Ordre : la surcharge/lib métier du scope l'emporte sur le défaut générique locale-aware (delegate), qui l'emporte sur le repli en intégré, qui l'emporte sur la clé brute. Jamais de throw sur clé absente. fallback remplace la clé brute en dernier recours.

label() honore le même repli en que ZcrudLocalizations.of — sans delegate monté, une clé générique connue rend son libellé en ('save' → 'Save') au lieu de la clé brute. On passe par ZcrudLocalizations.of (qui retombe sur la table en si le delegate n'est pas monté) puis, si le delegate est monté mais la clé absente de sa locale, on retente explicitement la table en de repli avant fallback/key.

Décision de forme : fonction top-level label(...) (plutôt qu'une extension sur BuildContext — évite de polluer l'espace des méthodes de BuildContext et reste explicitement importable via le barrel).

Implementation

String label(BuildContext context, String key, {String? fallback}) {
  final fromScope = ZcrudScope.maybeOf(context)?.labels?.maybeResolve(key);
  if (fromScope != null) return fromScope;
  final fromLocale = ZcrudLocalizations.of(context).maybeResolve(key);
  if (fromLocale != null) return fromLocale;
  final fromEn = _enLabels[key];
  if (fromEn != null) return fromEn;
  return fallback ?? key;
}
