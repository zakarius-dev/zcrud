Le kind sous lequel le type dynamique de value a été enregistré, si l'association est univoque — strictement équivalent à kindOfType(value.runtimeType), mêmes trois cas de contrat que kindOf (null si absent, StateError si ambigu).

Cas d'usage : le point d'entrée de sérialisation d'un moteur générique non borné — Map<String, dynamic> toMap<T>(T? item) — ne peut appeler ni kindOf<T>() (la borne T extends Object ne couvre pas un T implicitement Object?), ni fournir un Type utile quand seul l'item est en main. Résoudre depuis l'instance est alors la voie naturelle : registry.kindOfInstance(item) puis encode(kind, item).

Limite runtimeType vs types génériques : la résolution se fait sur le type dynamique exact de value, qui peut différer du type statique enregistré — un sous-type non enregistré rend null, et deux instanciations génériques distinctes (Foo<A> vs Foo<B>) sont deux types distincts pour la table. Pour les modèles concrets émis par le codegen (le cas nominal), type statique et runtimeType coïncident.

Implementation

String? kindOfInstance(Object value) => kindOfType(value.runtimeType);
